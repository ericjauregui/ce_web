# Site UX review — September 27, 2026

The strongest improvements are checkout error recovery and trustworthy order updates. The existing dark background, champagne-gold palette, imagery, and wholesale positioning are cohesive enough to preserve. A broad visual redesign is not the priority.

This initial review covered the local working tree, including existing edits to `templates/base.html` and `static/css/styles/connect.css`. The findings below describe that original snapshot. The subsequent implementation is documented at the end of this report. Impact rankings reflect observed task friction and potential consequences, not measured conversion lift.

## Proposed shared UX standards

- **Validation:** every required field gets an inline message, `aria-invalid`, and an associated description. Focus the first invalid field, keeping it clear of the fixed navigation and bottom action bar. Apply the same behavior to Name and Company Name as to the existing validated fields.
- **Order updates:** use one shared request/error pattern across catalog, product detail, and cart. Check HTTP success before showing a saved state; preserve or restore the last confirmed quantity on failure; show a retryable, announced error. Handle pending actions consistently and prevent rapid overlapping updates from displaying stale values. Extend the same pattern to removal and item notes.
- **Labels:** connect visible labels with each input, give the phone-country and phone-number controls distinct names, and name repeated quantity/removal controls with their product code. Preserve existing optional versus required fields.
- **Destructive actions:** use a clearly described confirmation for Clear Order, or implement a genuine undo that restores quantities and notes. Prefer undo for single-item removal where feasible. Do not silently turn a decrease from one to zero into unrecoverable removal.
- **Search:** show “No items found for ‘…’,” retain the query, offer Clear search / Browse catalog, and suggest searching by product code or collection. Announce the result state. Keep the existing Full Catalog route.
- **Action wording:** use “Add to order,” “Review order,” “Continue to order details,” and “Send order request” for the distinct steps. Reuse “Browse catalog” for the shared catalog-return action. Preserve the promise that wholesale pricing and availability are confirmed afterward and no payment is taken here.
- **Hierarchy:** use a filled gold treatment for the main next step, outlined buttons for secondary actions, and a quieter but clearly labeled destructive action. Keep the existing brand colors and page-specific layouts.
- **Counts:** distinguish styles from total quantity everywhere, preserving the current underlying units and calculations. Avoid “items” meaning different things in different places.
- **Touch:** aim for roughly 44px touch areas on frequently used mobile controls, while retaining compact visual icons where appropriate. Reflow the cart at narrow widths instead of enlarging controls until the table overflows. This is a usability target, not a claim that every measured control fails WCAG.

Accessible labeling and announced feedback follow W3C guidance on [labels and instructions](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) and [status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). WCAG 2.2's AA [minimum target-size criterion](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) uses 24×24 CSS pixels with exceptions, including spacing; the larger touch target above is a design recommendation.

## Implementation after approval

All seven numbered recommendations have been implemented locally:

1. Name and Company Name have explicit validation messages. Submission focuses and scrolls to the first invalid field.
2. Catalog, product detail, and cart use shared, serialized order requests. Quantities come from the successful server response; rejected changes restore the last confirmed display. Errors are announced and controls recover. Note text is retained on failure, and navigation waits for note saves.
3. Checkout fields have associated labels. Phone country selection has its own name, and quantity/removal controls identify their product code. The visible plus and minus symbols are unchanged.
4. Cart removal (including decreasing to zero) keeps the row dimmed with an inline Undo action and animated countdown ring showing seconds remaining for 30 seconds. Clear Order dims its rows and shows Undo Clear in the card. Undo restores quantities and notes, survives refresh in the same tab, and preserves newer edits. Expired content fades away; failed removal leaves the live item intact, and failed Undo remains retryable during its window. Signed, session-bound snapshots expire on the server and are invalidated after order submission. Catalog and product-detail removal retain their confirmations.
5. Empty searches identify the query and explain that nothing matched inside the standard shaded, gold-bordered card. Clear Search is an outlined action in the lower-right corner of that card.
6. Buttons that open the information form say Checkout; the form heading matches. Submit Order is reserved for final submission. Product detail uses a filled gold main action. Summary counts distinguish styles from total quantity.
7. Catalog and product-detail quantity controls have 44px tap areas. Following visual review, the cart retains its compact table, collapsed mobile Note controls, and compact footer. Its heading stays centered on one line between Catalog and Contact Us, and narrow screens keep every table action visible. Below 768px, removal uses a compact × with a product-specific accessible name; desktop retains Remove. Cart code badges use rounded rectangles matching nearby controls. Full Catalog, Clear Search, View All, and Jump to Top now share a 40px secondary-button style, and the collections toggle shares its border and corners. Primary CTAs retain their emphasis. Navigation and other footer controls have larger touch areas. The default WhatsApp position respects the order bar while retaining manual dragging.

The new UX E2E journeys are in `tests/e2e/e2e_ux.py`. They cover accessible checkout validation, rejected quantities on all three surfaces, failed add requests, failed and retried note saves, Clear Order failure and Undo, empty-search recovery, floating-control behavior, and responsive layouts. A dedicated cart journey checks the centered single-line heading, compact rows, unclipped actions, note saving, and clearing across 11 viewport widths from 320 to 1440 CSS pixels. The existing commerce flow now checks Clear Order with its Undo action. Six additional journeys in `tests/e2e/e2e_cart_undo.py` cover item recovery, clear recovery, refresh, independent Undo groups, preserved newer edits, failed restore retries, expiry, tampering, and session isolation.

Existing work on homepage loading and Connect styling was preserved. These changes have not been committed or deployed.

Final verification: **45/45 browser E2E tests passed**, with a further **6/6 Undo journeys passed in WebKit**. The final suite includes responsive layout, matching secondary-button styles, countdown progress at 60/30/1 seconds, recovery failures, notes, server-side expiry, and session isolation. Responsive checks cover 320 through 1440 CSS pixels. The final artifact manifest is verified with `--check-source`. This remains simulated browser evidence, not physical-device testing. The cart-recovery test stubs background video transport to avoid blocking the single-threaded local server; dedicated reel playback tests remain in the full suite.
